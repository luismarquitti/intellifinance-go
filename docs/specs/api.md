# IntelliFinance Technical Specification: REST API & JSON Contracts

- **Document ID**: SPEC-002-API
- **Status**: Authoritative / Production-Ready
- **Specification Standard**: OpenAPI 3.0.3 & RFC 7807 Problem Details
- **Router Engine**: `go-chi/chi/v5` with `oapi-codegen` Strict Server Generation
- **Authentication**: JWT Bearer Token (RFC 7519) + Pre-Shared Secret Webhook Headers

---

## 1. API Architecture & Standards

### 1.1 Design Principles
1. **Spec-First Architecture**: All endpoints and schemas conform to the OpenAPI 3.0 specification. Go server boilerplate and strict interface signatures are auto-generated via `oapi-codegen`.
2. **Predictable REST Conventions**: Standard HTTP verbs (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`) with appropriate status codes (`200 OK`, `201 Created`, `202 Accepted`, `204 No Content`, `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `409 Conflict`, `422 Unprocessable Entity`, `500 Internal Error`).
3. **Consistent Pagination Envelope**: All collection endpoints return a standardized metadata wrapper containing `page`, `limit`, `total`, `total_pages`, and `items`.
4. **RFC 7807 Problem Details**: All errors return structured JSON conforming to `application/problem+json`.
5. **Idempotency & Concurrency**: Critical mutation endpoints accept an optional `Idempotency-Key` header. Ingestion and sync operations return `202 Accepted` with a job tracking ID.

### 1.2 Global Request & Response Headers

| Header | Type | Description | Required |
|---|---|---|---|
| `Authorization` | String | Format: `Bearer <jwt_token>` | Yes (except `/auth/login` and `/auth/refresh`) |
| `Content-Type` | String | `application/json` or `multipart/form-data` | Yes (for mutation requests) |
| `X-Request-ID` | UUID | Traceability UUID propagated through structured logs | Optional (generated by Chi middleware if omitted) |
| `X-IntelliFinance-Webhook-Secret` | String | Webhook authentication token for Pluggy callbacks | Yes (for `/open-finance/webhook`) |

### 3.8 Internal Task Queue Webhooks (Cloud Tasks Push Endpoints)

In GCP Production mode, Google Cloud Tasks dispatches background jobs via authenticated HTTP POST requests targeting private endpoints under `/internal/tasks/{task_type}`.

#### `POST /internal/tasks/{task_type}`
Executes a queued background task (`task:ingest_statement`, `task:sync_open_finance`, `task:categorize_transaction`).

- **Authentication Middleware**: `GoogleOIDCMiddleware`
  - Validates `Authorization: Bearer <google_id_token>` using `google.golang.org/api/idtoken`.
  - Verifies token signature against Google JWKS (`https://www.googleapis.com/oauth2/v3/certs`).
  - Verifies Audience (`aud == https://api.intellifinance.app`) and Service Account Email (`email == intellifinance-tasks@<project>.iam.gserviceaccount.com`).
  - Requests failing OIDC verification are rejected with `401 Unauthorized` without executing handlers.
- **Path Parameters**:
  - `task_type` (string): e.g., `task:ingest_statement`, `task:sync_open_finance`, `task:categorize_transaction`
- **Request Headers**:
  - `Authorization`: `Bearer <google_id_token>` (Mandatory)
  - `X-CloudTasks-QueueName`: GCP Queue Name
  - `X-CloudTasks-TaskExecutionCount`: Current retry attempt counter
- **Request Body** (`application/json`):
```json
{
  "task_id": "projects/intellifinance-prod/locations/southamerica-east1/queues/ingestion-queue/tasks/12345",
  "task_type": "task:ingest_statement",
  "tenant_id": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee",
  "payload": {
    "job_id": "99999999-8888-7777-6666-555555555555",
    "storage_uri": "gs://intellifinance-ingestion-prod/tenant-aaa/statement_20260924.ofx",
    "account_id": "22222222-3333-4444-5555-666666666666",
    "source_type": "OFX"
  }
}
```
- **Responses**:
  - `200 OK`: Task completed successfully; Cloud Tasks acknowledges task as completed.
  - `4xx / 5xx`: Task execution failed; Cloud Tasks retries with exponential backoff up to `max_attempts = 5` before dead-lettering.

```go
package middleware

import (
	"context"
	"net/http"
	"strings"

	"google.golang.org/api/idtoken"
)

// ValidateGoogleOIDCToken validates Google Cloud Tasks OIDC bearer tokens
func ValidateGoogleOIDCToken(expectedAudience, serviceAccountEmail string) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			authHeader := r.Header.Get("Authorization")
			if !strings.HasPrefix(authHeader, "Bearer ") {
				http.Error(w, `{"error":"missing OIDC bearer token"}`, http.StatusUnauthorized)
				return
			}
			token := strings.TrimPrefix(authHeader, "Bearer ")

			payload, err := idtoken.Validate(r.Context(), token, expectedAudience)
			if err != nil {
				http.Error(w, `{"error":"invalid Google OIDC token"}`, http.StatusUnauthorized)
				return
			}

			if email, ok := payload.Claims["email"].(string); !ok || email != serviceAccountEmail {
				http.Error(w, `{"error":"unauthorized caller identity"}`, http.StatusForbidden)
				return
			}

			next.ServeHTTP(w, r)
		})
	}
}
```
